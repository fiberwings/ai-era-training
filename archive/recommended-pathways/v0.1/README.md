## Import into the planner

1. Open [Training Planner](../training-planner/Training-Planner.html).
2. Select **Scenario & exports → Import scenario JSON**.
3. Choose [Recommended-Training-Pathways.json](Recommended-Training-Pathways.json), then select **Load JSON**.
4. Review **Learning components**, **Audience paths** and **Path coverage**. Each path and component begins its rationale with its review status.
5. Export reloadable JSON to retain changes. Review and reconcile those changes into this maintained source before publishing a revised pathway version.

Import creates a separate scenario with a new local ID and an “(imported)” name suffix. Re-importing creates another copy; it does not overwrite a saved plan. Review labels are stored as metadata and visible rationale text, not automatic workflow gates. A local edit does not automatically reset these descriptive labels: update the review decision explicitly when promoting revised content.

The [learner app](../learning-path/index.html) now consumes this source directly. Run `node learning-path/scripts/build.mjs` from the repository root to rebuild it after an intentional source update. Publication preserves native component variants, displays review labels and offers an explicit standard/coached route choice at L2/L3. Proposed internal learning stays upcoming until its delivery status is Ready.

## Maintain and rebuild

Edit the JSON scenario for selections, internal briefs, audience composition, review status, owners, dates and version. Keep each rationale's opening review label consistent with its metadata. Preserve the saved AI use cases item, stable IDs and user-reviewed choices. Variants retain the historical differences between architecture, assurance, forensics, red-teaming and IAM branches without assigning extra exercises through shared components.

The guide, internal-brief register and coverage record are generated by [scripts/build.mjs](scripts/build.mjs); do not edit generated copies independently. The script uses the scenario's exact [catalogue snapshot](../training-planner/catalogue-history/ff6d5a46d0450171.json), validates it against the declared model version/revision, checks references and preserves the distinction between assessed and planned coverage. Calculation-module hashes are recorded in the coverage output.

From the repository root:

```sh
node recommended-pathways/scripts/build.mjs
node recommended-pathways/scripts/build.mjs --check
```

An intentional catalogue/model update needs a decision review, updated identities and a new pathway version. Do not merely stamp a new snapshot onto old selections. Archive a released decision package before replacing it if an immutable previous edition is required. Annual scheduling and delivery commitments belong in a subsequent delivery plan.
