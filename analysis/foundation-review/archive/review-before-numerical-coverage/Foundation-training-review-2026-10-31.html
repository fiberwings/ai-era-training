  • N3.1 Hallucination — Complete: Explain confident wrong answers; practise recognising and verifying one in an approved tool.
  • N3.2 Sycophancy — Build: Compare leading and neutral requests; recognise agreement that follows the user’s view.
  • N3.3 Context loss — Build: Demonstrate a lost constraint in a long conversation and how to restore it.
  • N3.4 Non-determinism — Build: Repeat the same request and explain why outputs differ.
  • N3.5 Prompt injection — Build: Demonstrate instructions hidden in a document and how to respond safely.
  • N3.6 Automation bias — Complete: Demonstrate over-trust; require an independent human judgement.
  • N3.7 Counter-habits — Complete: Add explicit source checks, independent-first judgement and output sampling.
N4 — Responsible AI use
  • N4.1 Data leaving the bank — Complete: Turn generic data-choice reflection into actual bank data-flow rules.
  • N4.2 Confidentiality and client data — Complete: Apply the bank’s client/confidential-data restrictions to the diligence exercise.
  • N4.3 Intellectual property — Build: Explain permitted inputs, ownership/reuse risks and when to seek IP advice.
  • N4.4 AI supply chain — Build: Explain risks from third-party models, Skills, connectors and their information sources.
  • N4.5 Regulation — Build: Have Compliance explain applicable AI-literacy duties and regional regulatory expectations.
  • N4.6 The bank's rules — Build: Apply approved-tool rules, agent delegation limits, approval requirements and escalation.
N5 — AI security risks and threats
  • N5.1 AI-enabled social engineering and impersonation — Build: Ad hoc awareness: phishing, tailored deception and voice/video impersonation; verify identity independently.
  • N5.3 AI-enabled intrusion — Build: Explain AI-assisted vulnerability discovery, malware generation and automated intrusion.
  • N5.4 Attacks on the bank's AI — Build: Provide attack examples involving the bank’s own AI systems.
  • N5.5 What changes for defence — Build: Explain changes in attack speed/volume and the need for independent identity checks.
  • N5.6 Recognising AI-enabled attacks — Build: Practise recognising an AI-enabled attack in the learner’s cyber domain.
  • N5.8 Overview of AI security risks — Build: Teach six categories with examples/precautions: instruction manipulation, disclosure, unsafe output handling, excessive actions/permissions, compromised components/sources and disruption/resource consumption.
N6 — Working with AI — L1
  • N6.1 Delegation — Apply: Apply the existing delegation exercise to a suitable bank task; check success criteria.
  • N6.2 Context — Apply: Apply the existing description exercise using permitted information, examples and constraints.
  • N6.3 Discernment — Apply: Apply the existing discernment exercise to work outputs; verify the presented argument, not imagined internal reasoning.
  • N6.4 Accountability — Apply: Adapt the existing diligence statement to the bank’s disclosure and accountability expectations.
  • N6.5 Choosing a model — Complete: Practise choosing both an available model and an effort level for a task.
  • N6.6 Context window and memory — Build: Recover lost context; manage long sessions and enabled persistent memory separately.
  • N6.7 Platform for the data — Build: Choose the actual approved platform for each bank data classification.
  • N6.8 Own work with AI — Complete: Support daily use on suitable work tasks within bank rules; review examples of practice.
